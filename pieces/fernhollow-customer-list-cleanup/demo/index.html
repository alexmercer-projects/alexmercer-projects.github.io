Data cleanup · CSV and Excel · Python

250 messy rows in. 211 clean customers out.

A made-up restaurant supply company in northern New England had a customer list pasted together from an old CRM export, a trade show sign-up sheet and a spreadsheet someone kept on the side. I wrote a script that fixes what can be fixed safely, merges the repeats, writes down every change, and hands back a short list of things a person should decide.

02 · What got fixed

Thirteen rules, each one boring on purpose

Every fix follows a written rule, and a rule only fires when the right answer is clear from the value itself or from the rest of the file. The numbers are cells changed in this file.

03 · Repeats

34 repeat rows, merged without losing anything

Two rows count as the same customer when they share an email or a phone number and the business names agree, or when the names match and the ZIP does too. The row with the most recent order is kept, its blanks are filled from the other row, and anything that disagrees goes into Notes instead of being thrown away.

Looked like repeats, kept apart on purpose

Merging two real customers is worse than leaving a repeat in, so these stayed separate.

    04 · Left for a person

      Running it

      • Plain Python 3, standard library only. The Excel workbook needs openpyxl; without it you still get every CSV.
      • Columns are found by name, so a file with “Company” instead of “Business Name” still works.
      • The rules live in one file in plain lists: the account types, the state spellings, which states have one area code. Changing them for another business is a small edit.
      • 37 tests cover each rule, the repeat matching and a full run on the sample file.

      07 · For a real list

      How I'd handle yours

      1. Look at a sample first. Fifty rows or so is enough to see which problems the file really has and which columns matter.
      2. Agree on the rules. What counts as the same customer, which spellings map to what, what should never be changed. Written down before anything runs.
      3. Run it and send back the review list. You get the clean file, the change log and the short list of questions only you can answer.
      4. Fold in your answers and keep the script. The next export can go through the same rules.

      Concept demo. Fernhollow Supply Co. is a made-up business, and so is every customer in the file: the towns, people, 555-01xx phone numbers and example.com emails. The messy file was generated by tools/make_sample.py to look like a real export. No real customer data was used, and this is not client work.
